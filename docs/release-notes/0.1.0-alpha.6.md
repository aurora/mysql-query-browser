# QueryMole 0.1.0-alpha.6

**QueryMole** is a revival of the classic MySQL Query Browser: the original Windows user interface, unchanged,
rebuilt with Free Pascal and Lazarus for current MySQL (5.7 to 9) and MariaDB (10.11, 11.4), on Windows and Linux.

- **Linux now uses Qt 6** instead of GTK2: the same look on every desktop (Qt's Fusion style), runs natively on
  Wayland as well as on X11, and scales with the desktop.
- **No more frozen window when the connection dies:** a window left open over standby or after the VPN went away
  stays usable; the lost connection is noticed within about 30 seconds.

**This is an alpha.** It is meant for people who want to try it and report problems. Use a test account or a test
server, keep your own backups, and expect faults (see below). QueryMole is not affiliated with Oracle; "MySQL" is a
trademark of Oracle.

## Downloads

- **Windows (64 bit), with updates:** [`QueryMole-win-Setup.exe`](https://github.com/aurora/querymole/releases/download/v0.1.0-alpha.6/QueryMole-win-Setup.exe).
  Installs for the current user (no administrator rights) into `%LOCALAPPDATA%\QueryMole`. The installer is not
  signed yet, so Windows SmartScreen may warn: "More info", then "Run anyway".
- **Windows (64 bit), portable:** [`QueryMole-0.1.0-alpha.6-win64.zip`](https://github.com/aurora/querymole/releases/download/v0.1.0-alpha.6/QueryMole-0.1.0-alpha.6-win64.zip).
  Unpack and run `querymole.exe`. No updates: download the next version and replace the folder.
- **Linux (x86_64), with updates:** [`QueryMole.AppImage`](https://github.com/aurora/querymole/releases/download/v0.1.0-alpha.6/QueryMole.AppImage).
  Make it executable (`chmod +x`) and run it from a folder you can write to (for example `~/Applications`), so that
  it can replace itself when it updates.
- **Linux (x86_64), without updater:** [`QueryMole-0.1.0-alpha.6-x86_64.AppImage`](https://github.com/aurora/querymole/releases/download/v0.1.0-alpha.6/QueryMole-0.1.0-alpha.6-x86_64.AppImage).
- Both AppImages bring Qt 6 and the other libraries and need glibc 2.34 or newer (RHEL 9, Ubuntu 22.04, Debian 12,
  Fedora 35 and newer). From the system they take libstdc++, OpenGL (libglvnd) and the font libraries (fontconfig,
  freetype, harfbuzz), which every desktop has. They run on Wayland and on X11. Without FUSE 2 installed, start them
  with `--appimage-extract-and-run`. The AppImages are larger than before (about 38 MB), mostly because of Qt's
  Unicode library.
- macOS: not yet.
- [`SHA256SUMS`](https://github.com/aurora/querymole/releases/download/v0.1.0-alpha.6/SHA256SUMS): checksums of the
  four files above (`sha256sum -c --ignore-missing SHA256SUMS`).

The other files of the release (`*.nupkg`, `releases.*.json`, `assets.*.json`, `RELEASES*`,

## Updates

**Help > Check for Updates ...** in 0.1.0-alpha.5 finds this release, downloads and installs it, then restarts the
program. On Linux the update replaces the GTK2 program by the Qt 6 one in the same file; your settings and stored
connections stay as they are. It works in the Windows installation and in `QueryMole.AppImage`; in the portable zip
and in the AppImage without updater the entry is disabled. Nothing is checked or downloaded unless you choose the
menu entry.

## Changes since 0.1.0-alpha.5

- **Linux: Qt 6 instead of GTK2** (ADR-0044). The program draws with Qt's Fusion style and its light palette on every
  desktop (ADR-0045); it does not follow the desktop's theme or dark mode. The forms were reviewed against the GTK2
  version one by one; fixed on the way: the cut-off first option under "Details >>" in the connect dialog, a wrapped
  prompt in the bookmark dialog, overlapping lines in the About dialog, and a menu bar and combo box lists that looked
  squeezed. The SQL editor and the forms use the same fonts as before (Bitstream Vera Sans Mono and the free Tahoma
  stand-in).
- **Lost connections** (ADR-0043): the keep-alive check runs in the background, and connections give up after about
  30 seconds without an answer from the server (20 seconds when connecting). Before, a window left open over
  standby could freeze for about a quarter of an hour once the server became unreachable. Long-running queries are
  not affected. Checked on Linux with dropped packets; on Windows the same socket limits apply but have not been
  tried that way yet.
- **Linux:** quitting the program ended with an internal error (exit code 217) after the window had closed; it now
  ends cleanly.
- **Packages:** the shipped libraries no longer contain folder names of the machine they were built on.

## What works

Connecting (TLS "preferred" with fallback), stored connections, the schema tree, the SQL editor with
highlighting, running queries, the result grid with editing, several result tabs, EXPLAIN, scripts with
breakpoints, export to CSV, HTML, XML, Excel and PLIST, the help panel (the reference comes from the connected
server), the table editor, options, text search and the regular expression importer. An automated suite runs
against MySQL 5.7, 8.0, 8.4, 9 and MariaDB 10.11 and 11.4.

## Known problems

- **Linux on Wayland:** started from a terminal, the program prints messages from the Qt toolkit about combo boxes
  and mouse grabbing; they are harmless. If dragging (splitters, column widths, drag and drop) misbehaves, start it
  with `QT_QPA_PLATFORM=xcb` (it then runs through XWayland) and tell us.
- **Linux:** the window became unresponsive once after loading about two million rows. Not reproduced. As in the
  original, every row of a result is kept in memory, so very large results need a lot of it; add a `LIMIT`.
- Real mouse and keyboard use, drag and drop, bookmarks and history, and the field viewer have not been worked
  through on every platform.
- **Linux on a scaled desktop:** the program is laid out in pixels for 96 dpi; Qt scales the whole window with the
  desktop's scale factor.
- **Linux:** passwords can be stored as "Plaintext" or "Obscured" only (no keyring); no global hot keys.
- Parts of the window look different under Qt on Linux than on Windows (for example the captions of group boxes sit
  above their frame).
- If an update fails, download the release by hand and tell us what happened (Velopack writes
  `%LOCALAPPDATA%\QueryMole\velopack.log` on Windows and `/tmp/velopack_QueryMole.log` on Linux).

More in the [README](https://github.com/aurora/querymole/blob/v0.1.0-alpha.6/README.md) and in
[docs/linux-port.md](https://github.com/aurora/querymole/blob/v0.1.0-alpha.6/docs/linux-port.md).

## What changed against the original

This release changes what users see in a few places on purpose: the name and artwork (QueryMole), the version
(0.1.0 alpha.6, "based on MySQL Query Browser 1.2.4 beta"), the About dialog (credits of the revival, the copyright
notice, the licence note and the source address), the settings folder, the removed menu entries of products that no
longer exist, the bug report entries pointing to this project, the update entry and, on Linux, a free stand-in for
the Tahoma font (Wine's, LGPL, shipped without its embedded bitmaps) that the forms are laid out for, and Qt's Fusion
style with slightly more space in the menu bar and combo box lists. The decisions are in `docs/adr/` (ADR-0017,
ADR-0026, ADR-0028, ADR-0030 to ADR-0033, ADR-0037, ADR-0038, ADR-0044, ADR-0045).

## Reporting problems

<https://github.com/aurora/querymole/issues>, with the version (Help > About), the operating system (and desktop,
with Wayland or X11), the server and its version, what you did in the last seconds, and, if the program ended, the
file `querymole.error.txt` next to it; with `QBR_TRACE=1` the program also writes `querymole.trace.txt`.
