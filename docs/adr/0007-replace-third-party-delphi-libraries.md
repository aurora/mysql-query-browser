# ADR-0007 — Replace third-party Delphi libraries with LCL equivalents and thin shims

- Status: Accepted
- Date: 2026-10-08
- Deciders: Harald Lapp (project owner)

## Context

Dependency analysis (`tools/unit_deps.py`) of the connection dialog alone
shows 35 units / ~52.9k lines, of which only ~8.7k are the project's own code;
the rest is third-party: the TNT Unicode Controls (~25k lines), PNGImage,
`gnugettext` (dxgettext), `Unicode` and friends. The main window pulls in 79
units / ~145k lines. Porting the third-party code is neither necessary nor
sensible: the LCL is Unicode throughout and ships most of what those libraries
provided.

Usage in the sources is narrow: about 50 `TTnt*` classes, 16 `Wide*`
functions, `_()` (685 calls) and `TranslateComponent` (1 call); the
`bindtextdomain`/`UseLanguage` calls occur only in the program file.

## Decision

- **TNT Unicode Controls:** each `TTntFoo` is a type alias of the LCL class
  `TFoo`, in units that keep the original names (`TntStdCtrls`, `TntForms`,
  ...), generated by `tools/gen_tnt_shims.py`, so `uses` clauses stay
  unchanged. The 16 `Wide*` helpers are small wrappers in `TntSysUtils` /
  `TntSystem`.
- **Virtual trees:** `laz.virtualtreeview_package` shipped with Lazarus 4.8
  (class `TLazVirtualStringTree`).
- **SQL editor:** SynEdit with `SynHighlighterSQL` replaces UniCodeEditor.
- **PNG:** the LCL's `TPortableNetworkGraphic`; `PNGImage` is a shim adding
  `Draw`/`DrawFaded` (the project's own `PNGTools` is ported).
- **Regular expressions:** FPC's `regexpr` (the same TRegExpr library).
- **Translations:** `gnugettext` is replaced by a ~250-line unit that reads the
  existing `.po` files directly from
  `<dir>/<lang>/LC_MESSAGES/<domain>.po`, ignoring fuzzy entries, with
  `pt_BR` → `pt` fallback and `msgstr[0]` for plurals.
- **Dropped or placeholder:** the Internet Explorer control (help/embedded
  browser), `TRichEdit` (shown as `TMemo`), `TAnimate` (shown as an empty
  panel) until real replacements exist.

## Consequences

Positive:

- An estimated 100k lines of third-party code are not ported at all (main
  window closure of 145k lines minus an estimated 30–40k of own code).
- Original `uses` clauses and class names keep working.
- Existing `de`, `el_GR`, `ja`, `pl`, `pt_BR` translations stay usable without
  a `msgfmt` step.

Negative / costs:

- Aliases hide behavioural differences: the TNT classes worked on UTF-16
  `WideString`, the LCL on UTF-8 `String`. Code that indexes into text or uses
  `Length` on non-ASCII strings can behave differently and has to be reviewed
  while porting.
- `TranslateComponent` handles only `Caption` and `Hint`; the original
  translated more properties. Plural forms beyond the singular are not
  supported.
- A hand-written `.po` reader is a small piece of infrastructure to maintain.
- Placeholders (`TRichEdit`, `TAnimate`) are visible gaps against the
  original.

## Alternatives considered

- **Port the TNT sources.** Rejected: ~25k lines of Delphi-specific code whose
  whole purpose the LCL already provides.
- **FPC `gettext` unit.** Rejected: reads `.mo` files only and has no
  dxgettext-style API; would need `msgfmt` in every build.
- **Lazarus `Translations` unit.** Rejected: built around `resourcestring`
  identifiers; the code base calls `_('English text')` throughout.
- **Rewrite call sites to native LCL API instead of shims.** Rejected for now:
  a larger diff against the original for no behavioural gain; can be done
  later per unit.
